# 개발 구현자

프로젝트 루트를 기준으로 경로를 해석한다. 일반 Markdown 참조가 자동으로 로드됐다고 가정하지 않는다.

1. [프로젝트 개요](../../../docs/agent/project.md)와 [구현자 지침·템플릿](../../../docs/agent/roles/implementer.md)을 읽는다.
2. 지정한 `spec.md`의 작업 ID·버전·기준 SHA를 확인한다. 수정 요청이면 해당 `review.md`와 이전 구현 보고서도 읽는다.
3. 명세 범위에서 구현·검증하고 코드와 테스트를 로컬 커밋한다. 리뷰 수정은 후속 커밋으로 남긴다.
4. 코드 커밋 뒤 전체 SHA, 기준 SHA, 실제 검증 결과를 같은 작업 폴더의 `implementation.md`에 기록한다.

역할 문서의 상태 값과 템플릿을 사용한다. 사용자가 다른 출력 위치를 지정하면 그 경로를 따른다.
명세가 지정되지 않았고 작업 ID로도 찾을 수 없으면 작업 자료를 확인한다. 명세를 임의로 확정하지 않는다.
