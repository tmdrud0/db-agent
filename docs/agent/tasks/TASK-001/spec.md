## 제약과 상태 처리

- 기존 `/init_session`, `/run_session`, `/health` 응답 구조와 공식 러너가 읽는 상태 필드를 유지한다.
  health의 에이전트 이름과 서버 제목은 새 기준선에 맞게 갱신한다. worker는 계속 1개다.
- 정상 입력의 한 세션에서 모델 호출은 1회, 유효한 생성 응답이 있으면 제출은 1회다.
  같은 세션의 후속 `/run_session`은 저장된 결과를 반환하고 모델·DB 호출을 반복하지 않는다.
  실패한 요청을 내부에서 자동 재시도하지 않는다. 지원하는 오류 경로는 실패 상태를 저장하며
  새 시도는 `reset: true`로 새 세션을 만든 경우에만 허용한다. 예상 밖 message 타입 오류 후
  외부에서 같은 세션을 다시 호출하는 동작은 버전 2의 지원 범위 밖이다.
- 제출 비용 3 bird-coins와 저예산 최종 제출 규칙을 유지한다.
  모델 호출 비용은 bird-coins와 별개이며, 제출하지 않은 생성 실패에 제출 비용을 부과하지 않는다.
- `passed`, `reward`, `phase_completed`, `has_follow_up`은 공식 응답을 기준으로 기록한다.
  SQL 내용이나 모델 설명으로 성공을 추정하거나 보상 0.7을 하드코딩하지 않는다.
- Phase 1 성공 후에도 후속 문제가 있으면 Phase 2를 풀거나 `/phase_transition`을 호출하지 않는다.
  `phase1_completed: true`, `phase2_completed: false`, `task_done: false`로 두고
  `loop_stopped: true`와 Phase 1 기준선 종료 사유를 기록한다.
  후속 문제가 없는 공식 성공이면 `task_done: true`를 기록할 수 있다.
  오답이면 단계 성공과 전체 완료를 false로 두고 제출 결과를 반환하며 종료한다.
- 모델 인증·요청·timeout·응답 형식 오류와 채점 HTTP·응답 계약 오류는 정상 오답과 구분한다.
  기존 오류 응답 계약을 유지하면서 오류 출처를 알 수 있게 한다. 제출 연결 오류는 채점 결과 미확인이다.
  오류에 대해 가짜 `passed: false` 제출 결과를 만들지 않는다. 예상 밖 message 타입 오류의
  HTTP 500 및 실패 저장 누락은 버전 2에서 수용한 제한이다.
- 모델 호출 기록은 기존 러너가 보존하는 `adk_events` 등에 남긴다.
  요청 모델, 응답 모델(제공될 때), 호출 횟수, 생성 SQL, 응답 usage(제공될 때), 설정값과 소요 시간을
  결과 JSON에서 확인할 수 있어야 한다. `/submit` 인자·공식 응답·예산은 기존 `tool_trajectory`에 남긴다.
  별도 관측 시스템이나 가격 계산 기능은 만들지 않는다.
- API 키, 인증 헤더, `.env`, GT·테스트 케이스, `private/`, `results/`, `vendor/`, 가상환경과 로컬 설정을 커밋하지 않는다.
  키는 state·결과·예외·로그에도 포함하지 않는다. 모의 테스트의 키는 명백한 가짜 값만 사용한다.
- 공식 러너·원본 문제·GT·채점기는 수정하지 않는다. 기존 oracle은 별도 환경 확인 절차로 유지하고 모델 입력과 연결하지 않는다.

## 완료 조건

- AC-1: 모의 모델 HTTP 테스트에서 정확한 엔드포인트·모델 ID·인증·문제 입력을 확인한다.
  모델 요청에는 허용된 문제와 DB 이름만 포함되고 state의 임의 추가 필드는 포함되지 않는다.
- AC-2: 정상 SQL 응답이 변경 없이 공식 `/submit`에 전달되고 공식 결과가 state와 반환 응답에 기록된다.
  전체 코드 펜스 처리, 비어 있는 content, 잘린 응답을 확인한다. 변경 SQL을 임의로 차단하지 않는다.
- AC-3: 오답·Phase 1 성공·후속 문제 있음/없음·저예산을 모의 채점으로 검증한다.
  Phase 2 호출과 추가 제출은 없으며 보상·단계 완료·프로그램 종료를 구분한다.
- AC-4: 반복 실행·동일 세션 동시 요청·reset 동작에서 호출 횟수를 확인한다.
  정상 결과와 지원하는 ModelError/GradingError 경로에서 세션 재호출만으로 모델 또는 제출 요청이 중복되지 않는다.
  R-1의 예상 밖 message 타입 오류 이후 재호출 보장은 제외한다.
- AC-5: 키 누락, 모델 HTTP 오류/timeout/잘못된 JSON·빈 content·잘림, 채점 HTTP 오류가 명시적 오류로 반환된다.
  모델 실패 시 제출은 0회다. 비밀값이 오류·state·호출 기록에 남지 않는다.
  R-1의 예상 밖 message 타입 오류를 502로 정규화하는 것은 제외하고 HTTP 500 제한으로 남긴다.
- AC-6: 기존 테스트와 새 계약 테스트가 통과하고 API 설정·실행 문서가 실제 명령과 일치한다.
  결과 이름과 health 표시에서 새 기준선을 식별할 수 있고 호출·SQL·공식 결과 기록을 확인할 수 있다.
  평가 전 기존 에이전트를 종료·재시작하며, 이전 서버 설정을 자동 검증하는 R-2 보완은 요구하지 않는다.
- AC-7: 사용자 키가 설정된 환경에서 실제 한 문제를 동시성 1로 실행해
  모델 생성 1회 → 공식 제출 1회 → 채점 결과 수신을 확인한다. 정답이어야 한다는 조건은 없다.
  코드 SHA, 문제 ID, 모델·요청 설정, 실행 명령, 호출·제출 근거와 공식 결과를 구현 보고서에 기록한다.
  키·계정·네트워크·DB 환경 때문에 실행하지 못하면 이유와 미검증 범위를 기록하고 AC-7을 충족으로 쓰지 않는다.

## 조사할 사항

- 현재 예외 메시지를 그대로 반환하는 `agent/server.py`가 모델 오류에 인증정보를 노출하지 않도록 확인한다.
- 지원하는 오류 경로의 실패 상태 처리를 확인한다. R-1의 예상 밖 형식 오류 후 재요청 보완은 제외한다.
- 현재 테스트의 빈 SQL 제출·Phase 2 전환 기대값은 이번 명세에 맞게 교체한다.
- 평가 스크립트는 이미 떠 있는 에이전트를 재사용할 수 있으므로 평가 전 사용자가 기존 에이전트를 종료한다.
  현재 코드로 새로 시작해 의도한 모델·설정을 사용한다. 자동 설정 비교는 요구하지 않으며 사용자의 서버를 임의 종료하지 않는다.
- 공식 결과 집계에는 오류 항목도 `total_reward: 0`으로 들어갈 수 있다.
  오류 필드와 오류 건수를 함께 확인하고 이를 정상 0점 문제로 설명하지 않는다.
- Phase 1 전용 실행의 Phase 2 점수는 개선 여부의 지표로 해석하지 않는다.
  전체 보상을 재정규화하지 않고 공식 Phase 1 결과와 오류 건수를 중심으로 보고한다.
