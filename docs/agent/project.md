# 프로젝트 개요

## 목표와 현재 상태

BIRD-Interact Lite의 데이터·도구·채점 과정을 사용해 자체 에이전트 루프를 개선하고,
AI agent engineer 지원 시 설계 선택과 평가 근거를 보여주는 프로젝트다.
현재는 모델 없이 빈 SQL을 한 번 제출하는 연결 확인 코드이며 완성된 에이전트가 아니다.
초기 실행 코드 기준 커밋은 `066bb2f33db65660bee62348ab224db9f22e8ee7`이다.
개별 작업은 이 값을 고정 사용하지 말고 명세 작성 당시 실제 기준 SHA를 기록한다.

## 주요 코드와 계약

| 위치 | 책임 |
| --- | --- |
| `agent/server.py` | 공식 러너와 연결하는 세션 API |
| `agent/loop.py` | 문제 해결 흐름, 제출 이후 상태 갱신 |
| `agent/environment.py` | 공식 서비스 HTTP 호출 |
| `scripts/prepare-benchmark.ps1` | 외부 코드·데이터, 의존성, GT 병합 준비 |
| `scripts/run-evaluation.ps1` | Docker·에이전트 실행, 공식 러너 평가 |
| `scripts/run-smoke.ps1`, `scripts/run-dev30.ps1` | 한 문제·전체 또는 고정 30문제 평가 |
| `tests/` | 로컬 API 계약·개발 세트 검증 |

러너가 `/init_session`으로 상태를 전달하고 `/run_session`으로 실행을 요청한다.
에이전트는 공식 DB 서비스에 `/submit`을 호출하며, 채점 응답을 상태에 반영해 러너에 반환한다.
Phase 1 성공에 후속 질문이 있으면 사용자 시뮬레이터의 `/phase_transition`도 호출한다.
현재는 후속 질문을 저장하고 멈추며, 재시도와 Phase 2 풀이는 앞으로 구현한다.
현재 HTTP 어댑터에는 제출·단계 전환만 있고 나머지 도구는 아직 없다.

세션은 `(mode, task_id)`별로 메모리에 저장한다. 같은 세션 실행은 lock으로 보호한다.
Uvicorn worker는 1개, 평가 기본 동시성은 10이며 현재 스크립트 범위는 1~16이다.
`reset: false`는 기존 세션을 재사용하고 `true`는 새 상태로 초기화한다.
실행 종료와 문제 성공은 다르다. 공식 응답 없이 점수·단계 완료를 성공으로 만들지 않는다.
네트워크 오류는 정상적인 오답 0점과 구분한다.

## 평가 원칙

정답·테스트 케이스는 평가 환경에서만 사용한다. 에이전트가 읽는 입력이나 메모리에
정답 파일을 넣지 않는다. 도구를 확장할 때 공식 환경이 숨기는 지식 정보를
로컬 파일에서 가져와 우회하지 않는다. 원본 문제·GT·채점 규칙을 바꾸는 작업은
루프 개선 작업과 구분하고 명세에 목적과 영향을 적는다.

공식 Phase 1/2 보상은 0.7/0.3이다. 개발용 30문제는 공개 유형 비율 195:105에 따라
조회 20개·변경 10개로 고정했다. 문제별 추가 가중치는 없다.
GT·API 키·`private/`·`results/`·`vendor/`·가상환경·로컬 도구 설정은 Git에서 제외한다.
보고서에 민감한 정답 SQL·키·개인 설정을 붙이지 않는다.

2026-10-14 실제 30문제 연결 검증은 oracle 평균 0.96, 빈 SQL 평균 0.0이었다.
oracle Phase 2 실패는 `museum_M_4`, `cross_db_M_5`, `virtual_M_4`, `news_M_4`였다.
원본 문제를 수정하거나 제외하지 않았다. 이 결과는 모델 성능 측정 결과가 아니다.
점수 비교에는 동일한 문제 목록·코드 SHA·모델 설정·동시성·실행 조건을 기록한다.

## 검증과 실행

프로젝트 루트의 PowerShell에서:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\scripts\run-smoke.ps1
.\scripts\run-dev30.ps1
```

첫 명령은 가짜 HTTP 응답을 쓰는 계약 테스트이며 실제 DB 채점과 다르다.
평가 명령은 oracle을 먼저 실행한 뒤 자체 에이전트를 평가하며 결과 파일을 갱신한다.
전체 평가 명령은 `run-smoke.ps1 -Limit 300`이다. 전체 300문제 완료는 아직 확인하지 않았다.
현재는 모델 API를 호출하지 않는다. 모델이나 질문 도구 추가 시 API 설정·의존성·비용도 고려한다.
새 환경 준비와 제약은 [setup.md](../setup.md), 실행 개요는 [루트 README](../../README.md)를 따른다.

역할 문서는 기본 맥락이다. 구체적인 작업 범위·유지할 동작·완료 조건은 해당 `spec.md`를 따른다.
사용자가 이미 승인한 작업을 문서 때문에 다시 승인받지 않는다.
