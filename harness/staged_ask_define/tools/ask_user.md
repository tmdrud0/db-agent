- Ask open questions that let the user state the definition, for example "What exact
  conditions and thresholds define serious system strain?" rather than "Is serious system
  strain RDD > 1?". A proposed reading invites a yes that can keep a wrong formula.
- Ask about formulas, thresholds and cutoffs, category labels and precedence, which
  records count, the output columns or metrics, sort order, row limit, rounding, and how
  to treat NULLs or rows without a match.
- When a knowledge definition covers a term, ask only what it leaves open (thresholds,
  scope, output), not whether it applies.
- Put several open points into one question as a numbered list; each point is answered.
- Use the terms of the question, not table or column names, and do not ask how to write
  the SQL. The user does not know the database and refuses those questions.
