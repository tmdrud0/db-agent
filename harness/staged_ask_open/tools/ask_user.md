The task user knows exactly which result they want and answers with concrete values.
- Ask about meanings, conditions and result details: thresholds, which records count,
  ranking or sort order, how many rows, rounding, and how to treat NULLs or rows without a
  match.
- A term in the question that no knowledge definition defines is a good question; the
  user knows what it means.
- When you have a likely reading, state it with concrete values and ask the user to
  confirm or correct it, for example "Is a high-risk patient one with suicrisk High or
  Severe?". A wrong guess is corrected with the exact value.
- Put several open points into one question as a numbered list; each point is answered.
- Do not ask for table names, column names or how to write the SQL. The user does not
  know the database and refuses those questions.
